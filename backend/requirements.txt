# Pinned to the tested versions (was >= ranges) for reproducible builds and
# supply-chain safety — an unpinned `pip install` could pull an untested or
# compromised newer release into the deployed image. Bump deliberately.
# fastapi 0.121.0 is the first release whose starlette ceiling (<0.50.0) admits
# the patched starlette 0.49.2 below. Earlier fastapi (through 0.120.x) capped
# starlette at <0.49.0, which is why this pair was held back previously.

# Pin starlette explicitly so `pip install` is reproducible (unpinned, a fresh

# 0.49.2, which sits inside fastapi 0.121.0's supported range.

# OpenTelemetry auto-instrumentation (ADOT). Supplies the
# `opentelemetry-instrument` wrapper the Dockerfile CMD runs under, which traces
# FastAPI requests and boto3 calls (Bedrock, DynamoDB, S3) with no application
# code changes — this is what makes extraction, validation and query traceable
# end to end. Spans go to X-Ray and, via infrastructure/modules/tracing, into
# the CloudWatch `aws/spans` index.
#
# opentelemetry-instrumentation-threading is pinned alongside it because the
# distro does NOT constrain it: pip otherwise resolves the newest release, which
# demands a different opentelemetry-instrumentation version than the distro
# pins, leaving an incoherent set that `pip check` flags.

opentelemetry-instrumentation-threading==0.61b0
